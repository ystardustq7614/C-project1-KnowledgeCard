## 1.界面菜单乱码问题

这是经典的 **Windows 控制台编码问题**。源文件是 UTF-8 编码，但 Windows 控制台默认使用 GBK (CP936)，导致中文乱码。

**修复方法**：在 `main()` 函数开头设置控制台代码页为 UTF-8。

Edited main.cpp
Ran command: `g++ -std=c++17 -fexec-charset=UTF-8 -o project1.exe src/*.cpp 2>&1`

编译通过。修复内容很简单：

**原因**：源文件是 UTF-8 编码，但 Windows CMD 默认使用 GBK (CP936)，UTF-8 字节序列按 GBK 解读就变成乱码。

**修复**：在 `main()` 开头加了一行：
```cpp
#ifdef _WIN32
    system("chcp 65001 > nul");
#endif
```
这会将控制台代码页切换到 UTF-8 (65001)，`> nul` 用于隐藏 `chcp` 自身的提示输出。

**编译命令也加了保险**：
```bash
g++ -std=c++17 -fexec-charset=UTF-8 -o project1.exe src/*.cpp
```
`-fexec-charset=UTF-8` 确保 g++ 将字符串字面量按 UTF-8 编码。


# 2.cardid显示问题

对于创建知识卡片的人来说，可能他是第一次创建知识卡片，但是显示的cardid却并不是1（因为这是在所有card中计算的），毫无疑问这肯定会对用户造成困惑。

对于普通用户而言，他们只关心“这是我的第几张卡片”，完全不关心“这是整个系统数据库里的第几条记录”。全局 `cardid` 暴露给用户不仅会造成强烈的认知困惑，在真实商业系统中还会暴露系统数据规模。

- **解决方案（表现层映射 —— 最保守安全）：隐藏全局 ID，采用“动态展示序号”。** 底层数据结构（`cardId`）和文件格式保持不变，它仅作为系统内部主键。但在 UI 层面（如查看卡片列表时），程序临时生成 `1, 2, 3...` 的序号显示给用户。当用户选择修改或删除时，输入的是这个序号（如 `1`），程序在内存中自动将序号 `1` 映射回真实的 `cardId`。
    
    - _优点_：对底层逻辑和文件结构零破坏，改造成本低，容错率高。

**原理**：
核心思想是：**切断用户输入与底层数据的直接联系**。
在目前的 V1 中，系统打印出 `cardId`，用户输入 `cardId`。
而在方案 A 中，我们在每次打印列表时，建立一个临时的 **映射表（`vector<int> displayMap`）**，记录“展示序号”到“真实数据索引”的对应关系。用户眼中只看到 `1, 2, 3...`，系统在拿到用户的输入 `1` 后，通过 `displayMap[1 - 1]` 瞬间找回底层真实的数据。

【核心代码示例（修改前对比）】

以 `src/card.cpp` 中的 `viewAllCards()` （查看全部卡片）为例：

**1. 修改展示函数，隐藏底层 `cardId`：**
```cpp
// 以前是打印 c.cardId，现在改为传入一个 displayIndex 打印
void printCardBrief(int realIndex, int displayIndex) {
  const Card &c = cards[realIndex];
  // 注意这里打印的是 displayIndex，而不是 c.cardId
  cout << "  [" << displayIndex << "] " << c.title << " | " << c.subject
       << " | 难度:" << c.difficulty << " | 掌握:" << c.mastery
       << "\n";
}
```

**2. 核心逻辑重构：引入 `displayMap` 映射表**
```cpp
void viewAllCards() {
  clearScreen();
  cout << "==============================\n";
  cout << "     全部知识卡片\n";
  cout << "==============================\n";

  // 【核心】建立映射表：存储满足条件的卡片在全局 cards 容器中的真实索引
  vector<int> displayMap; 
  int displayIndex = 1; // 永远从 1 开始给用户看

  for (size_t i = 0; i < cards.size(); ++i) {
    const Card &c = cards[i];
    if (c.userId != currentUserId || !c.active)
      continue;
      
    displayMap.push_back(i); // 记录真实索引
    printCardBrief(i, displayIndex); // 打印时给用户看动态序号
    displayIndex++;
  }

  if (displayMap.empty()) {
    cout << "当前没有卡片。\n";
  } else {
    cout << "\n共 " << displayMap.size() << " 条卡片。\n";

    // 交互逻辑：用户输入的是【显示序号】，而不是 cardId
    cout << "\n输入卡片【序号】查看详情，或直接回车返回：";
    string line;
    getline(cin, line);
    line = trim(line);
    
    if (!line.empty()) {
      int choice;
      if (parseInt(line, choice)) {
        // 【核心】安全性校验与映射还原
        if (choice >= 1 && choice <= displayMap.size()) {
          int realIndex = displayMap[choice - 1]; // O(1) 还原真实索引
          printCardDetail(realIndex); // 直接调用，无需再次 for 循环查找！
          pauseScreen();
          return;
        } else {
          cout << "输入的序号超出了范围。\n";
        }
      }
    }
  }
  pauseScreen();
}
```

**3. 对于“新增卡片”的提示修改：**
```cpp
// 在 addCard() 尾部：
// 修改前：cout << "\n卡片创建成功！编号：" << c.cardId << "\n";
// 修改后：内部 ID 对用户毫无意义，直接隐藏
cout << "\n卡片创建成功！\n"; 
```

【优点总结】
1. **代码更简单**：省去了原来 `parseInt(line, id)` 之后还要 `for` 循环遍历寻找对应 `cardId` 的麻烦，直接通过 `displayMap[choice - 1]` 下标访问，性能和逻辑都更好。
2. **完全解耦**：之后无论我们怎么加入“按掌握度排序”或“按学科筛选”，筛选出来的结果只需要塞进 `displayMap`，用户看到的永远是从 1 开始的干净列表。
3. **安全**：即使用户恶意输入其他用户的底层 `cardId` 也无法越权，因为他只能在当前生成的安全映射表 `displayMap` 范围内进行选择。

# 1.登陆时发现账号不存在

【当前目标】
定位 `project1-v1.2` 中中文账号注册后登录提示“用户不存在”的原因。

【排查结论】
主要原因是**中文用户名的输入编码与文件存储编码不一致**。

证据：

- `data/users.txt` 中第 2、3 个账号实际存在，且字段格式正确：
  - `2|张钰清|zhang761480526|2026-04-24`
  - `3|钟李康|likang666|2026-04-27`
- [storage.cpp](<E:\VS project\code_c\project1-v1.2\src\storage.cpp:52>) 的 `loadUsers()` 会按 `|` 拆分并加载用户，当前数据文件不是字段缺失问题。
- [user.cpp](<E:\VS project\code_c\project1-v1.2\src\user.cpp:18>) 的 `findUserIndexByName()` 使用 `users[i].username == username` 做**字节级精确比较**。
- [utils.cpp](<E:\VS project\code_c\project1-v1.2\src\utils.cpp:18>) 的 `initTUI()` 只设置了：
  ```cpp
  SetConsoleOutputCP(65001);
  ```
  也就是只设置了**输出编码 UTF-8**，没有设置输入编码 `SetConsoleCP(65001)`。

因此：  
文件里的中文用户名是 UTF-8 字节，但 Windows 控制台输入中文时可能仍按 GBK/OEM 代码页进入程序。中文字符的字节不一致，比较失败，于是 `findUserIndexByName()` 返回 `-1`，登录逻辑就输出“用户不存在”。

验证到的字节差异：

```text
张钰清 UTF-8: E5 BC A0 E9 92 B0 E6 B8 85
张钰清 GBK:   D5 C5 EE DA C7 E5
```

ASCII 用户名如 `alice` 不受影响，因为 ASCII 在 UTF-8 和 GBK 下字节一致。

【临时解决】
在运行程序前先执行：

```powershell
chcp 65001
.\project1.exe
```

然后再输入中文用户名测试。

【建议修复】
在 `initTUI()` 的 Windows 分支中补上：

```cpp
SetConsoleCP(65001);
SetConsoleOutputCP(65001);
```

必要时再统一数据文件编码为 UTF-8。当前 `users.txt` 本身看起来是 UTF-8，不需要先改数据。

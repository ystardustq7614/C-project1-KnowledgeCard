# 知识卡片与错题复习管理系统 V1.1 实现计划与项目骨架

## 1. 当前目标

在现有 V1 项目基础上，继续迭代一个 **低风险、高收益、结构不破坏** 的增强版本。

本次 V1.1 不推翻 V1 的核心设计，不替换持久化方式，不修改复习算法主线，而是在已有代码骨架上补充以下五项增强能力：

1. 错题转知识卡片
2. 多条件筛选与排序
3. 错因分类统计
4. 数据维护模块（查看 / 恢复逻辑删除记录）
5. 交互体验优化（表现层映射，隐藏全局 cardId/wrongId）

V1.1 的目标是：

- 进一步提升系统“学习场景”的完整性
- 让卡片与错题形成真实联动
- 提升查询、筛选、统计的可用性
- 让逻辑删除策略真正形成闭环

## 2. V1.1 功能范围（最终执行版）

## 2.1 必做增强功能

### 1）错题转知识卡片
支持将当前用户的一条有效错题转换为一张新知识卡片。

转换规则：
- `front = question`
- `back = correctAnswer + "\n错因分析：" + reason`
- 新卡片 `userId = 当前用户`
- 新卡片 `subject / chapter` 继承原错题
- 新卡片 `title` 可默认生成为：`[错题转卡片] + subject + chapter`
- 新卡片 `tags` 可默认设置为：`错题转化`
- 原错题保留，并更新 `linkedCardId`

约束：
- 仅允许转换当前用户 `active = true` 的错题
- 若 `linkedCardId != -1`，则提示“该错题已关联卡片”
- V1.1 默认 **一条错题只允许关联一张转换生成的卡片**

### 2）多条件筛选与排序
V1.1 不做复杂组合检索界面，只做 **单条件筛选 + 单字段排序**。

#### 卡片支持
筛选：
- 按学科筛选
- 按章节筛选
- 按标签筛选

排序：
- 按创建时间排序
- 按下次复习时间排序
- 按掌握度排序

#### 错题支持
筛选：
- 按学科筛选
- 按章节筛选

排序：
- V1.1 可先不单独提供错题排序菜单；若实现成本可控，可补充按创建时间 / 下次复习时间排序

说明：
- 所有筛选与排序仅作用于当前用户 `active = true` 的记录
- 默认界面不显示 `inactive` 记录

### 3）错因分类统计
在错题数据中正式引入 `errorType` 字段，用于记录错误类型并进行统计。

固定可选值：
- 概念不清
- 记忆错误
- 粗心
- 审题失误
- 计算错误
- 方法不会

V1.1 支持：
- 新增错题时录入 `errorType`
- 修改错题时修改 `errorType`
- 统计模块输出各错因类型数量分布

### 4）数据维护模块
为逻辑删除提供配套的查看与恢复能力。

V1.1 最小功能：
- 查看已删除卡片
- 查看已删除错题
- 恢复已删除卡片
- 恢复已删除错题

约束：
- 默认普通菜单仍然不显示 `inactive`
- 数据维护模块只处理当前用户自己的记录
- V1.1 暂不实现“彻底物理删除”

### 5）交互体验优化（表现层映射）
为了解决多用户场景下，全局自增 ID 暴露给用户导致的体验困惑，将卡片和错题的增删改查交互方式进行统一重构：
- 列表打印时隐藏底层真实的 `cardId` 和 `wrongId`。
- 在内存中生成动态映射表（`displayMap`），界面上显示连续的动态序号（如 1, 2, 3）。
- 用户的所有操作（查看详情、修改、删除）均通过输入“动态序号”完成。
- 底层文件格式和数据结构保持零侵入、零修改。

## 4. 数据结构调整

## 4.1 `WrongQuestion` 新增字段

在现有结构体中加入：

```cpp
string errorType;
```

推荐位置：
放在 `reason` 之后、`linkedCardId` 之前，保持语义连续。

更新后的错题结构体建议为：

```cpp
struct WrongQuestion {
    int wrongId;
    int userId;
    string subject;
    string chapter;
    string question;
    string correctAnswer;
    string wrongAnswer;
    string reason;
    string errorType;
    int linkedCardId;
    int mastery;
    int reviewCount;
    int correctStreak;
    int intervalDays;
    string createDate;
    string lastReviewDate;
    string nextReviewDate;
    bool active;
};
```

---

## 4.2 `linkedCardId` 在 V1.1 中正式启用

V1 中该字段仅作为预留字段；V1.1 起正式参与错题转卡片功能。

规则：
- 默认值为 `-1`
- 当错题成功转为卡片后，更新为新卡片 `cardId`
- 若不为 `-1`，视为该错题已关联转换卡片

说明：
- V1.1 中 `linkedCardId` 仍不参与复习调度
- 主要用于：
  - 判断是否已转换
  - 展示错题与卡片的关联关系

## 5. 文件格式调整

## 5.1 `wrongs.txt` 字段更新

V1 字段：
```text
wrongId|userId|subject|chapter|question|correctAnswer|wrongAnswer|reason|linkedCardId|mastery|reviewCount|correctStreak|intervalDays|createDate|lastReviewDate|nextReviewDate|active
```

V1.1 字段：
```text
wrongId|userId|subject|chapter|question|correctAnswer|wrongAnswer|reason|errorType|linkedCardId|mastery|reviewCount|correctStreak|intervalDays|createDate|lastReviewDate|nextReviewDate|active
```

示例：
```text
2001|1|高数|极限|求 lim sinx/x|1|0|忘记基本极限公式|概念不清|-1|30|0|0|1|2026-04-23||2026-04-23|1
```

## 5.2 数据兼容策略

如果 V1 已经有旧版 `wrongs.txt` 数据，需要先确定一条升级策略。

### 保守方案
V1.1 开发阶段直接采用 **新格式文件**，不兼容旧格式读取。

理由：
- 练手项目中实现格式迁移不是当前重点
- 能降低解析复杂度
- 更适合快速进入增强功能开发

### 增强方案
若想兼容旧格式，可在 `loadWrongs()` 中判断字段数：
- 旧格式：缺失 `errorType`，默认填空字符串或“未分类”
- 新格式：正常读取

V1.1 建议默认先采用第一种保守方案。

### 转换逻辑建议
`convertWrongToCard()` 流程：
1. 输入 `wrongId`
2. 按编号查找错题
3. 校验：
   - 记录存在
   - `active == true`
   - `userId == currentUserId`
   - `linkedCardId == -1`
4. 构造新卡片
5. 分配新 `cardId`
6. 写入 `cards`
7. 更新原错题 `linkedCardId`
8. 保存 `cards.txt` 与 `wrongs.txt`
9. 提示转换成功

## 13. 风险点与规避方式

### 风险 1：旧数据文件与新结构不一致
问题：`wrongs.txt` 增加 `errorType` 后，旧数据可能无法直接读取。

规避：
- 开发阶段直接采用新格式数据文件
- 若需要兼容旧数据，再单独补迁移逻辑

### 风险 2：错题转卡片导致重复转换
问题：同一错题可能被多次转为卡片。

规避：
- 使用 `linkedCardId` 判断是否已转换
- 发现已关联时直接拦截

### 风险 3：筛选与排序逻辑分散
问题：若在菜单层临时写筛选代码，后期会混乱。

规避：
- 将筛选与排序函数集中在 `card.cpp / wrong.cpp`
- 菜单层只负责调用

### 风险 4：逻辑删除恢复时越权
问题：用户可能恢复非自己的记录。

规避：
- 恢复操作必须校验 `userId == currentUserId`
- 仅允许恢复当前用户 `active = false` 的记录

---


## 14. 结论

V1.1 的最佳推进方式是：

> 先改对数据结构，再补统计，再做错题转卡片，接着完善筛选排序与数据维护，最后用表现层映射统一收口交互。

这样既不会破坏已有的 V1 工程，也能最大化提升项目的完整度和展示效果。

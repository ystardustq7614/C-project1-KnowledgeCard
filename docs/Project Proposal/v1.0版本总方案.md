# 知识卡片与错题复习管理系统 V1 方案

## 1. 项目定位

本项目是一个基于 **C++ 控制台** 的学习管理小系统，面向学生日常学习场景，提供知识卡片管理、错题记录、今日复习、复习日志与基础统计等功能，帮助用户完成 **“录入 — 复习 — 巩固”** 的学习闭环。

与普通信息管理系统不同，本系统在基础 CRUD 之外，引入了 **简化版间隔复习机制**：系统会根据用户每次复习结果，动态调整项目的下次复习时间，实现“不会就更快复习，会了就适当延后”的节奏。

---

## 2. 项目目标

构建一个 **功能完整、结构清晰、可运行、可验证、可继续迭代** 的 C++ 练手项目。

V1 的目标不是一次做成复杂的学习平台，而是优先交付一个稳定的最小可用版本，重点做到：

1. 支持多用户登录与数据隔离。
    
2. 支持知识卡片和错题的基本管理。
    
3. 支持生成“今日应复习”列表并完成一次复习流程。
    
4. 支持复习结果落盘、下次复习时间更新和日志记录。
    
5. 支持基础统计分析。
    

---

## 3. 核心用户场景

### 场景 1：录入知识点

用户登录后，新增一张知识卡片，填写学科、章节、标题、问题、答案、标签和难度，用于后续复习。

### 场景 2：记录错题

用户在做题后录入一条错题，保存题目、正确答案、错误答案和错因分析，作为重点复习内容。

### 场景 3：进行今日复习

系统自动筛选出今天到期的卡片和错题，生成待复习列表。用户依次复习，并对每条内容给出“不会 / 模糊 / 会”的反馈。

### 场景 4：查看学习情况

用户查看卡片数量、错题数量、今日待复习数量、掌握度分布等统计结果，了解近期学习状态。

- 卡片总数
    
- 错题总数
    
- 今日待复习数量
    
- 掌握情况统计
    
- 各学科数量分布
    
- 最近 7 天复习次数
    

统计总原则：

- 所有统计默认仅基于当前用户数据
    
- 对象统计只计算当前用户 `active = true` 的卡片和错题
    
- 日志频率统计只计算当前用户日志
    

统计口径固定如下：

- **掌握情况统计**：按 `0~39`、`40~69`、`70~100` 三档统计当前用户有效卡片与有效错题的数量
    
- **复习频率统计**：默认统计当前用户最近 `7` 天内的复习日志数量
    
- **学科分布统计**：分别统计当前用户有效卡片数和有效错题数，不包含 `inactive` 记录

- 空字符串检查

- 数值范围检查
    
- 菜单输入合法性检查
    
- 删除前确认
    
- 查询无结果提示

- `difficulty`：`1 ~ 5`
    
- `result`：仅允许 `0 / 1 / 2`
    
- `mastery`：不允许用户直接输入，由系统维护并保证范围为 `0 ~ 100`
    
- 菜单项：只允许当前菜单列出的整数选项

## 5. 技术选型与理由

### 技术栈

- 语言：C++
    
- 运行方式：控制台程序
    
- 数据存储：本地文本文件（`.txt`）
    
- 核心容器：`vector`
    
- 排序与任务生成：`vector + sort`
    
- 项目形态：单体程序
    

### 选择理由

1. **适合练手**：覆盖结构体、文件读写、容器、模块化、函数设计等核心知识点。
    
2. **依赖少**：无需引入数据库、图形库或复杂构建系统。
    
3. **启动快**：可直接从命令行运行，便于逐步实现和调试。
    
4. **可答辩**：既有完整管理流程，也有学习场景特色和复习算法亮点。

说明：

- `currentUsername` 仅用于界面显示，例如欢迎信息、当前用户提示等。

## 6.3 删除与记录状态策略

V1 对 **卡片** 和 **错题** 统一采用 **逻辑删除**，不做物理删除。

### 规则

- `active = true`：记录有效
    
- `active = false`：记录已删除 / 无效
    
- 删除操作的本质是将 `active` 置为 `false`
    
- 保存文件时，`inactive` 记录仍然保留
    
- 程序启动加载数据时，`inactive` 记录也会读入内存
    

### 默认处理范围

以下功能 **只处理 `active = true` 的记录**：

- 查询
    
- 列表展示
    
- 分类查看
    
- 统计分析
    
- 今日复习任务生成
    
- 复习流程
    

### 查询反馈约定

- 若按 `cardId` 或 `wrongId` 查询时命中了 `active = false` 的记录，V1 对普通用户统一按“不可见”处理。
    
- 系统提示统一为：**未找到有效记录**。
    
- V1 不向普通用户暴露“记录已逻辑删除但仍保留在文件中”的内部状态。
    

### 展示策略

- V1 默认界面不展示 `inactive` 记录
    
- `inactive` 记录主要用于防止误删和后续数据维护
    
- 如后续实现“数据维护模块”，可增加查看或清理无效记录的功能
    

### 说明

- V1 不单独设置“已归档”“已掌握”等复杂状态字段。
    
- 是否熟练主要通过 `mastery`、`intervalDays` 和 `nextReviewDate` 体现。
    
- `User` 在 V1 中不提供删除、封禁、恢复等功能，因此 **不设置 `User.active` 字段**。
    
- V1 的用户模块默认只处理已注册用户，不考虑无效用户状态。

## 7. 复习算法设计（V1 固定间隔法）

V1 采用 **固定间隔法**，不同时实现两套算法，保证逻辑清晰、易于调试。

## 7.1 新建卡片 / 错题的初始复习状态

为保证“今日复习”逻辑可直接工作，新增卡片或错题时统一初始化如下：

### 新增知识卡片

- `mastery = 50`
    
- `reviewCount = 0`
    
- `correctStreak = 0`
    
- `intervalDays = 1`
    
- `lastReviewDate = ""`
    
- `nextReviewDate = createDate`
    
- `active = true`
    

### 新增错题

- `mastery = 30`
    
- `reviewCount = 0`
    
- `correctStreak = 0`
    
- `intervalDays = 1`
    
- `lastReviewDate = ""`
    
- `nextReviewDate = createDate`
    
- `linkedCardId = -1`
    
- `active = true`
    

说明：

- 在 V1 核心流程中，`linkedCardId` 仅作为预留字段，不参与查询、统计、复习调度与删除逻辑。
    

### 设计说明

- 新建内容在创建当天就会进入“今日应复习”列表。
    
- 这样首轮演示时无需等待，也能直接体现复习流程。
    
- 错题的初始掌握度低于普通卡片，用于体现“错题更需要优先复习”的特点。
    

## 7.2 复习结果定义

- `0 = 不会`
    
- `1 = 模糊`
    
- `2 = 会`
    

### 更新规则

#### 当结果为“不会”

- `intervalDays = 1`
    
- `correctStreak = 0`
    
- `mastery = max(0, mastery - 15)`
    

#### 当结果为“模糊”

- `intervalDays = 3`
    
- `correctStreak = 0`
    
- `mastery = min(100, mastery + 3)`
    

#### 当结果为“会”

- `correctStreak += 1`
    
- `mastery = min(100, mastery + 10)`
    
- 间隔规则：
    
    - 若 `correctStreak == 1`，`intervalDays = 7`
        
    - 若 `correctStreak == 2`，`intervalDays = 15`
        
    - 若 `correctStreak >= 3`，`intervalDays = 30`
        

### 每次复习后统一更新

- `reviewCount += 1`
    
- `lastReviewDate = 今天`
    
- `nextReviewDate = 今天 + intervalDays`

## 8. 今日复习任务生成策略

系统启动或进入“今日复习”模块时：

1. 扫描当前用户的全部卡片和错题。
    
2. 过滤掉 `active = false` 的记录。
    
3. 找出 `nextReviewDate <= 今天` 的项目。
    
4. 转换为 `ReviewTask` 列表。
    
5. 构造任务时直接计算 `priority`。
    
6. 按 `priority` 从高到低排序，数值越大表示越应优先复习。
    

### 优先级公式（V1）

```text
priority = overdueDays * 10 + wrongBonus + (100 - mastery)
```

其中：

- `overdueDays = max(0, daysBetween(dueDate, today))`
    
- 仅对 `nextReviewDate <= today` 的记录计算优先级
    
- 若今天到期，则 `overdueDays = 0`
    
- `wrongBonus = 20`：错题固定加分
    
- 普通卡片 `wrongBonus = 0`
    
- `mastery` 越低，优先级越高
    

### 说明

- V1 不强制使用 `priority_queue`。
    
- 使用 `vector + sort` 即可满足需求。
    
- `ReviewTask` 是运行时临时结构，不必落盘。
    
- `ReviewTask` 仅保存排序所需的最终优先级值，生成任务后，排序阶段不再回查原始记录字段。
    
- 若优先级相同，可再按 `dueDate` 更早者优先作为次级排序规则。

## 9.4 文本输入约束（V1）

为降低解析复杂度，V1 明确限制：

- 所有文本字段均为 **单行输入**
    
- 文本中 **禁止包含 `|`**
    
- 自动去除首尾空格
    
- 空字符串不允许保存
    
- 可为主要文本字段设置最大长度
    

说明：

- V1 不支持多行文本输入。
    
- V1 不实现复杂字符转义。

## 10. 日期处理规则

V1 统一使用 `YYYY-MM-DD` 格式。

需要实现以下日期工具：

- 获取今天日期
    
- 判断日期是否合法
    
- 比较两个日期大小
    
- 在指定日期上增加若干天
    
- 判断某条记录是否到期
    
- 计算两个日期之间的天数差（供 `overdueDays` 使用）
    

说明：

- 复习调度依赖日期计算，因此需要保证日期函数可靠。
    
- 所有日期比较均使用统一格式字符串配合工具函数处理。

## 14.9 编号生成规则

V1 的编号生成统一采用以下策略：

- 新增记录时，扫描对应容器中的最大编号
    
- 新编号取 `maxId + 1`
    
- 即使旧记录已被逻辑删除，也 **不复用历史编号**
    

适用对象：

- `userId`
    
- `cardId`
    
- `wrongId`
    
- `logId`

## 16. 风险点与规避方式

### 风险 1：范围膨胀

问题：功能点过多，容易导致项目拖延。

规避：

- 严格以 V1 必做功能为边界。
    
- 增强项放到后续迭代。
    

### 风险 2：文件解析出错

问题：文本字段包含特殊字符会破坏分隔格式。

规避：

- 明确禁止输入 `|`
    
- 第一版只支持单行文本
    

### 风险 3：日期计算容易出错

问题：下次复习时间依赖日期加减逻辑。

规避：

- 封装独立日期工具函数
    
- 先单独测试日期模块
    

### 风险 4：删除语义不清导致逻辑分叉

问题：如果不明确逻辑删除与过滤范围，查询、统计、复习会出现不一致。

规避：

- 明确卡片和错题统一使用逻辑删除
    
- 所有前台功能默认只处理 `active = true`
    
- `inactive` 记录只保留在文件和内存中，供后续数据维护使用
    

### 风险 5：菜单与逻辑耦合过高

问题：所有逻辑堆在 `main.cpp` 中会难以维护。

规避：

- 按模块拆分头文件和源文件
    
- 菜单层只负责交互，不负责核心业务

## 17. 验收标准

满足以下条件即可认为 V1 完成：

1. 可注册并登录不同用户。
    
2. 不同用户的数据互不混淆。
    
3. 可新增、修改、删除、查询卡片和错题。
    
4. 可生成今日待复习列表。
    
5. 可完成一次复习并正确更新下次复习时间。
    
6. 可记录复习日志。
    
7. 可查看基础统计结果。
    
8. 程序退出后再次启动，数据仍能正确读取。

## 18. 已知限制

- 第一版仅支持控制台交互。
    
- 第一版仅支持单行文本输入。
    
- 密码可先明文存储，后续再做简单加密。
    
- 复习算法采用简化固定间隔法，不追求完整记忆模型精度。
    
- 不使用数据库，不支持网络同步。

# 知识卡片与错题复习管理系统 V1.2 实现计划与架构重构

## 1. 核心目标
V1.2 版本的核心目标是从“功能完备的电子记录本”迈向“智能化、高表现力的学习引擎”。
不仅要在业务上补充**测试练习**、**智能推荐**、**记忆衰减**和**彻底删除**机制，更要在架构上引入**高内聚、低耦合**的算法层设计，以便未来轻松接入更复杂的复习模型（如 FSRS），并在视觉上全面升维至半图形化终端（TUI）。

---

## 2. 功能范围与算法解耦设计（高内聚低耦合）
为避免业务逻辑和核心算法搅成一团，V1.2 引入 `algo_` 算法层隔离。
**设计美学要求**：所有 `algo_` 文件必须是“纯函数计算”，**禁止 `#include "globals.h"` 或直接读写全量 `cards` 向量**。算法层只接收标准数据类型结构体，输出计算结果，由外层业务（如 `review.cpp`）负责更新全局状态与落盘。

### 1) 简化 SM-2 (分离至 `algo_sm2`)
- **废弃**：原先让用户选择 0-5 分的高心智负担评分。
- **引入**：极简的三档反馈（1: 忘记-重置间隔； 2: 模糊-间隔不变； 3: 记牢-间隔拉长）。
- **纯函数签名**：`ReviewResult calculateNextReview(int oldMastery, int oldInterval, int score);`

### 2) 记忆热度衰减 (分离至 `algo_decay`)
- **机制**：当真实日期超过 `nextReviewDate` 达到设定的宽限期时，惩罚（降低）其 `mastery`，以模拟遗忘曲线。
- **纯函数签名**：`DecayResult calculateDecay(int currentMastery, int currentInterval, const string& nextReviewDate, const string& todayDate);`

### 3) 薄弱知识点智能推荐 (分离至 `algo_recommend`)
- **机制**：计算各个 `(学科, 章节)` 组合的平均 `mastery`，找出垫底的 Top 3 进行提醒。
- **输入输出**：传入所有卡片的轻量级摘录列表，传出排好序的分析结果。

### 4) 测试练习模块 (`practice.cpp`)
- 不同于普通的“到期复习”，测试练习是用户**主动**发起的“随机抽取 N 题自测”。系统只显示题目（Front），用户心算或输入后，系统再展示答案（Back）供自评。
- 练习成绩也可以选填计入复习频次。

### 5) 彻底物理删除 (`maintenance.cpp`)
- 一键执行垃圾回收，将内存中 `active == false` 的数据剔除，全量覆写 `cards.txt` 与 `wrongs.txt`。

### 6) 多条件组合查询界面
- 采用向导式问答：“请输入学科(回车跳过)->请输入章节(回车跳过)->请输入关键字”。内部走多条件取交集的过滤函数。

### 7) 原生 ANSI TUI 视觉重构 (`tui.cpp`)
- 利用 C++ 输出 ANSI 控制码，实现字体变色、高亮、粗体，并用 ASCII 字符（如 `┌ ─ ┐ │ └ ─ ┘`）包裹菜单和展示详情，彻底脱离原始的黑白流式输出。

## 4. 分阶段实施计划（粒度极细化）

### 阶段 A：算法基建与模块抽离（重构）
- **目标**：建立 `algo_sm2` 独立模块，将原来 `review.cpp` 里的面条式间隔计算代码剥离，并改造为三档评分。
- **涉及文件**：`algo_sm2.h/cpp` (新建), `review.cpp` (修改)
- **验证方式**：进入今日复习，输入评分 1/2/3，退出后去 `cards.txt` 观察该卡的间隔天数和掌握度是否严格按照新算法更新。

### 阶段 B：多条件查询与物理删除（数据层收尾）
- **目标**：补齐长期遗留的组合查询能力，提供物理清空回收站功能。
- **涉及文件**：`card.cpp`, `wrong.cpp`, `maintenance.cpp`
- **验证方式**：
  1. 走维护菜单一键物理删除，文本编辑器打开 `.txt` 文件确认已被抹除。
  2. 混合条件搜索，只返回完美满足所有交集条件的卡片。

### 阶段 C：记忆衰减与智能推荐闭环（智能化）
- **目标**：每次登录后，在主菜单首部利用 TUI 醒目地高亮提示薄弱章节；每日首次登录自动跑一遍全局衰减扫描。
- **涉及文件**：`algo_decay.h/cpp`, `algo_recommend.h/cpp`, `main.cpp` (加载流处触发扫描)
- **验证方式**：人为篡改某条记录的 `nextReviewDate` 为 30 天前，重新跑程序，主界面应该会冒出提示：“警告：检测到 X 条记录发生记忆衰减！”，并被列入今日复习。

### 阶段 D：测试练习模块（新业务流）
- **目标**：不影响复习主线，独立出一个类似于“模拟考试”的功能。
- **涉及文件**：`practice.h/cpp` (新建), `main.cpp` (挂载主菜单)
- **验证方式**：选择随机 10 题盲抽，流程连续，不需要频繁退回菜单。

### 阶段 E：全局原生 ANSI TUI 视觉升维（最终打磨）
- **目标**：用 `tui.cpp` 提供的边框、进度条、色彩高亮等 API，全盘替换项目中干瘪的 `cout << "=====";`。
- **涉及文件**：`tui.h/cpp` (新建), 全局所有涉及打印的模块。
- **验证方式**：程序启动后，标题变为带渐变色/纯色的 ASCII 艺术字，列表自带表格框线包裹，成功报错信息变为红绿底色。

## 5. 风险点与规避方式

### 风险 1：算法层被业务污染
- **问题**：如果在编写 `algo_recommend` 时贪图方便，直接 `#include "globals.h"` 去遍历全局变量，那就违反了“低耦合”。
- **规避**：严格限定 `algo_` 层的入参，它只能接 `vector<T>` 或者 `struct`，内部绝对禁止出现 `saveCards()` 这种业务级系统调用。

### 风险 2：ANSI 在 Windows CMD 默认禁用
- **问题**：导致满屏的 `[0m[31m` 乱码。
- **规避**：在 `main.cpp` 的 `main()` 函数第一行，强制注入 Win32 API 代码：
  ```cpp
  HANDLE hOut = GetStdHandle(STD_OUTPUT_HANDLE);
  DWORD dwMode = 0;
  GetConsoleMode(hOut, &dwMode);
  SetConsoleMode(hOut, dwMode | ENABLE_VIRTUAL_TERMINAL_PROCESSING);
  ```

### 风险 3：记忆衰减的雪崩效应
- **问题**：用户一个月没看，一登录发现全部记录掉到 0，产生极强挫败感弃坑。
- **规避**：设置最大衰减阈值（如每次扫描无论过期多久，掌握度最多掉 20%，间隔最多缩短一半）。

## 二、需要注意 / 微调的几个点

### 1. 错题菜单编号重排问题

> [!IMPORTANT]
> V1 现有错题菜单结构为 7 项：记录(1)、修改(2)、删除(3)、编号查(4)、关键字查(5)、分类查看(6)、全部(7)。方案中建议新菜单为 7 项（"分类查看"合并了筛选功能，新增了"错题转卡片"），但编号和描述与 V1 不同。

**现有 V1 错题菜单：**
```
1. 记录错题
2. 修改错题
3. 删除错题
4. 按编号查询
5. 按关键字查询
6. 分类查看
7. 查看全部错题
```

**方案建议菜单：**
```
1. 新增错题
2. 修改错题
3. 删除错题
4. 查询错题        ← 合并了编号查+关键字查？
5. 分类查看错题
6. 错题转知识卡片   ← 新增
7. 查看全部错题
```

**建议：** 保持 V1 现有菜单 1~7 不动，在末尾追加新选项即可：
```
1. 记录错题
2. 修改错题
3. 删除错题
4. 按编号查询
5. 按关键字查询
6. 分类查看
7. 查看全部错题
8. 错题转知识卡片    ← 新增
0. 返回主菜单
```

这样改动最小、不影响已有用户习惯。同理卡片菜单也建议在末尾追加排序查看。

### 3. `maintenance` 模块 vs 就地实现

方案建议新增 `maintenance.h/cpp`，同时又在 `wrong.h` 和 `card.h` 中也声明了 `showDeletedWrongsOfCurrentUser()` 和 `restoreWrong()` 等函数。

**建议：** 选择其中一种方案即可，不要两边都声明：
- **方案 A（推荐）：** 新建 `maintenance.h/cpp`，所有恢复/查看已删除记录的逻辑集中在此。`wrong.h` 和 `card.h` 不新增这些声明。

方案 11.2 中将 `printWrong(const WrongQuestion& w)` 列入 `wrong.h` 新增声明，但 V1 已有 `printWrongBrief(int index)` 和 `printWrongDetail(int index)`。

**建议：** 不需要新增 `printWrong()`。现有的 `printWrongDetail(int index)` 已经可以满足所有打印需求。如果维护模块需要打印已删除记录，直接复用 `printWrongDetail()` / `printWrongBrief()` 即可。

### 5. 数据兼容性建议

> [!TIP]
> 方案中建议"保守方案：不兼容旧格式"。但实现兼容的成本极低——只需在 `loadWrongs()` 中检查字段数量即可。建议采用兼容方案，仅需改动 2~3 行代码：

```cpp
// loadWrongs() 中，在 if (p.size() < 17) continue; 之后：
if (p.size() >= 18) {
    // 新格式：含 errorType
    w.errorType = p[8];
    w.linkedCardId = stoi(p[9]);
    // ... 后续字段偏移 +1
} else {
    // 旧格式：无 errorType
    w.errorType = "";
    w.linkedCardId = stoi(p[8]);
    // ... 保持原字段顺序
}
```

这样可以避免开发期间频繁手动清理测试数据。

### 6. `convertWrongToCard()` 的位置

方案将此函数放在 `wrong.h/cpp` 中。这是合理的，因为转换的主体操作是基于错题发起的。但实现时需要注意：
- 它需要 `#include "card.h"` 或至少访问 `cards` 全局容器和 `getNextCardId()`
- 这在当前项目中没有问题，因为 `globals.h` 已声明了全局容器，`storage.h` 提供了 `getNextCardId()`

# 知识卡片与错题复习管理系统 v1.3 后续迭代方案

## 1. 当前目标

在 v1.3.0 测试闭环版本之后，继续处理当前遗留的 5 个结构性问题：

1. E2E 只覆盖一条核心业务主链路，需要扩展到主要菜单分支全覆盖。
2. 中文自动化输入已在 v1.3.4 纳入总回归测试入口。
3. 文本字段已在 v1.3.3 支持多行和 `|`。
4. `algo_decay` 日期差已在 v1.3.2 统一为更准确的日期处理工具。
5. 项目命名需要全面标准化。

本轮后续迭代不建议一次性混合修改。以上问题会影响路径、命令、数据格式、输入流和测试脚本，必须分阶段推进。

---

## 2. 核心用户场景

### 2.1 开发者场景

- 开发者进入 `code_c/project1` 后，可以使用稳定命令编译、运行和测试。
- 项目目录、可执行文件、文档命令不再混用历史带版本命名。
- 一条总测试命令能覆盖主要业务分支，并能定位失败阶段。

### 2.2 使用者场景

- 用户可以输入包含中文、多行内容和 `|` 的卡片 / 错题文本。
- 用户可以长期使用真实数据，不因数据格式升级丢失旧记录。
- 复习衰减逻辑在跨月、跨年、闰年等日期场景下保持可解释和可测试。

### 2.3 测试维护场景

- E2E 脚本不只验证一条主链路，而是覆盖主要菜单入口。
- 中文输入有稳定 runner 和 fixture，不依赖 PowerShell 源码文件中的中文字符串。
- 存储格式升级有兼容性测试和迁移验证。

## 4. 推荐技术策略

### 4.1 命名标准化

采用稳定命名：

```text
目录名：project1
可执行文件：project1.exe
项目版本：写入 README、迭代方案和报告，不写入目录名 / exe 名
```

当前实际目录已是 `code_c/project1`，但文件和文档中仍残留历史带版本命名，需要集中清理。

### 4.2 日期工具统一

新增独立日期模块：

```text
src/date_utils.h
src/date_utils.cpp
tests/test_date_utils.cpp
tools/run_algorithm_tests.ps1  # 接入日期测试
```

推荐接口：

```cpp
bool parseDate(const std::string& text, Date& out);
bool isValidDate(const std::string& text);
int daysBetweenDates(const std::string& from, const std::string& to);
std::string addDaysToDate(const std::string& date, int days);
std::string todayDate();
```

`algo_decay` 不再内部近似计算 `year * 365 + month * 30 + day`，改为调用统一日期工具。

### 4.3 文本字段存储升级

继续保留“一行一条记录、字段以 `|` 分隔”的轻量文本存储，但对文本字段做编码：

```text
原始文本 -> encodeStorageField() -> 写入文件
文件字段 -> decodeStorageField() -> 载入内存
```

推荐转义规则：

| 原字符 | 存储形式 |
|---|---|
| `%` | `%25` |
| `|` | `%7C` |
| `\r` | `%0D` |
| `\n` | `%0A` |

优点：

- 文件仍保持单行记录，便于人工排查。
- 可兼容旧数据，旧数据没有转义时仍能读取。
- 新数据可以支持 `|` 和多行文本。

控制台多行输入建议采用结束标记：

```text
输入多行内容，单独输入 .end 结束
```

先对卡片正面 / 背面、错题题目 / 正确答案 / 错误答案 / 错因分析支持多行；用户名、密码、学科、章节、标签仍保持单行。

### 4.4 中文自动化输入

避免在 `.ps1` 源码中直接写大量中文测试输入。推荐方式：

```text
tests/fixtures/e2e_inputs/chinese_business_flow.txt
tools/run_utf8_automation.ps1
tests/test_chinese_input_flow.ps1
```

原则：

- 中文输入内容放在 UTF-8 文本 fixture。
- PowerShell 脚本只负责读取 UTF-8 文件并送入程序。
- 中文 E2E 验证读取数据文件，确认中文没有乱码。

### 4.5 E2E 分支覆盖

“全覆盖”在本项目中定义为：主要菜单分支至少有一条自动化 smoke / regression 流程，不追求所有非法输入排列组合。

建议新增：

```text
tests/e2e/
├─ test_user_flow.ps1
├─ test_card_flow.ps1
├─ test_wrong_flow.ps1
├─ test_review_flow.ps1
├─ test_practice_stats_flow.ps1
├─ test_maintenance_flow.ps1
└─ test_chinese_text_flow.ps1

tools/run_e2e_tests.ps1
```

`tools/run_all_tests.ps1` 后续改为调用 `tools/run_e2e_tests.ps1`。

## 6. 风险点与规避方式

| 风险 | 影响 | 规避方式 |
|---|---|---|
| 命名标准化遗漏旧路径 | 脚本或文档失效 | v1.3.1 集中处理，并用旧命名关键字扫描 |
| 日期工具改动影响复习逻辑 | 衰减和复习到期变化 | 先加日期单元测试，再替换算法调用 |
| 文本转义破坏旧数据 | 历史记录无法读取 | 读取端兼容旧格式，新增 fixture 覆盖旧数据 |
| 多行输入破坏菜单自动化 | E2E 输入序列错位 | 多行输入采用明确结束符 `.end`，并新增 E2E case |
| 中文输入在 PowerShell 5.1 下乱码 | 自动化不稳定 | 中文放入 UTF-8 fixture 文件，不写在 `.ps1` 源码中 |
| E2E 扩展过大 | 脚本维护困难 | 按模块拆分 case，并由 `run_e2e_tests.ps1` 汇总 |

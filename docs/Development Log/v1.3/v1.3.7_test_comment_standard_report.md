# v1.3.7 测试模块注释规范落地报告

## 版本号

- 当前版本：v1.3.7
- 对比版本：v1.3.6

## 本轮目标

在 v1.3.6 已完成源码注释规范治理的基础上，将 `注释要求.md` 的要求扩展到测试模块，补齐测试入口、测试 helper、E2E 分支脚本和 C++ 单元测试中的职责、约束、边界和断言口径说明。

## 解决的问题

- v1.3.6 的测试脚本虽然可运行，但脚本职责和测试边界主要靠文件名推断，新维护者不容易判断每个 case 覆盖什么、不覆盖什么。
- E2E 输入脚本依赖大量空行驱动 `pauseScreen()` 和菜单返回，缺少注释时容易被误删，导致后续菜单输入整体错位。
- 临时目录清理、`--data-dir` 数据隔离、UTF-8 输入、fixture 复制等测试约束没有集中说明，后续扩展测试时容易误读写真实 `data/`。
- C++ 算法/日期测试缺少测试目标说明，维护者不容易知道这些断言对应 README 中的哪些业务规则。

## 新增内容

- 为 `tools/run_all_tests.ps1` 新增总验收入口说明，明确默认清理 `.test_tmp`、子测试数据隔离和失败退出码契约。
- 为 `tools/run_cli_checks.ps1` 新增 CLI 检查说明，明确 fixture 复制、`--data-dir`、`PROJECT1_DATA_DIR`、退出码和自动修复字段断言。
- 为 `tools/run_algorithm_tests.ps1` 新增纯函数测试说明，强调算法测试不链接 `main/storage`，避免隐藏全局依赖。
- 为 `tools/run_e2e_tests.ps1` 新增 E2E 汇总说明，明确主程序只构建一次，各 case 必须独立初始化数据目录。
- 为 `tools/run_utf8_automation.ps1` 新增 UTF-8 手动复现脚本说明，明确它不是断言型测试入口。
- 为 `tests/e2e/common.ps1` 新增公共 helper 模块说明，覆盖路径保护、临时数据初始化、字段解码和断言 helper 的契约。
- 为 `tests/test_e2e_flow.ps1`、`tests/test_chinese_input_flow.ps1` 和 `tests/e2e/*.ps1` 新增模块级注释和关键输入/断言说明。
- 为 `tests/test_algorithms.cpp`、`tests/test_date_utils.cpp` 新增测试职责、边界覆盖范围和轻量断言说明。

## 修改内容

## 已知问题 / 剩余问题

- 测试脚本仍存在少量 helper 重复实现，尤其是主链路和中文链路没有完全复用 `tests/e2e/common.ps1`。

- E2E 仍以主要路径和关键分支回归为目标，不覆盖所有非法输入排列组合。

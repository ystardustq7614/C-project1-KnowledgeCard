# v1.3.2 日期工具与衰减算法修正报告

## 【版本号】

- 当前版本：v1.3.2
- 对比版本：v1.3.1

## 【本轮目标】

新增统一日期工具，替换 `algo_decay` 内部近似日期差，让复习衰减在跨月、跨年和闰年场景下可解释、可测试。

## 【解决的问题】

- v1.3.1 中 `algo_decay.cpp` 自行解析日期，并使用 `year * 365 + month * 30 + day` 估算日期差。
- 该估算在 1 月 31 日到 2 月 3 日这类跨月场景下会把 3 天误算为 2 天，导致应触发的衰减没有触发。
- `utils.cpp` 和 `algo_decay.cpp` 各自维护日期逻辑，后续修改容易产生规则不一致。
- 日期测试原本只间接覆盖算法结果，没有独立验证日期解析、闰年和日期加减。

## 【新增内容】

- 新增 `src/date_utils.h`：定义 `Date` 结构体和统一日期接口。
- 新增 `src/date_utils.cpp`：实现日期解析、合法性校验、日期差、日期加减和今天日期。
- 新增 `tests/test_date_utils.cpp`：覆盖日期工具核心边界。
- `tools/run_algorithm_tests.ps1` 新增日期测试构建与运行步骤。

## 【修改内容】

- `src/utils.cpp` 不再维护独立日期计算细节，改为调用 `date_utils`。
- `src/algo_decay.cpp` 删除内部近似日期差函数，改为调用 `daysBetweenDates()`。
- `tests/test_algorithms.cpp` 新增跨月和闰年衰减测试，防止算法退回近似日期差。
- README、`docs/testing.md`、`v1.3后续迭代方案.md` 更新为 v1.3.2 状态。

## 【代码级变更】

- `src/date_utils.h`
  - 新增 `Date`。
  - 新增 `parseDate()`、`isValidDate()`、`daysBetweenDates()`、`addDaysToDate()`、`todayDate()`。

- `src/date_utils.cpp`
  - 新增 `isLeapYear()`、`daysInMonth()` 等内部辅助逻辑。
  - 使用公历日期序号算法计算日期差，不依赖 `mktime` 的本地时区结果。
  - 非法日期差返回 `0`，非法日期加减返回原字符串，保持旧调用的容错风格。

- `src/utils.cpp`
  - 删除本文件内部的日期解析、闰年、月份天数、`mktime` 日期差实现。
  - `getTodayDate()` 包装 `todayDate()`。
  - `addDays()` 包装 `addDaysToDate()`。
  - `daysBetween()` 包装 `daysBetweenDates()`。
  - 保留 `compareDate()` 和 `isDateDue()` 的原业务接口。

- `src/algo_decay.cpp`
  - 新增 `#include "date_utils.h"`。
  - 删除内部 `daysBetweenDates()` 近似实现。
  - `calculateDecay()` 的逾期天数来源统一为 `date_utils`。

- `tests/test_date_utils.cpp`
  - 新增日期解析测试。
  - 新增非法日期测试。
  - 新增同日、跨月、跨年、闰年日期差测试。
  - 新增日期加减测试。

- `tests/test_algorithms.cpp`
  - 新增跨月逾期衰减测试。
  - 新增闰年 2 月逾期衰减测试。

- `tools/run_algorithm_tests.ps1`
  - 先编译运行 `test_date_utils.exe`。
  - 再编译运行 `test_algorithms.exe`。
  - 算法测试链接 `src/date_utils.cpp`。

## 【影响范围】

- 影响日期解析、日期合法性、日期差、日期加减和记忆衰减逾期天数计算。
- `review.cpp`、`stats.cpp`、`maintenance.cpp` 等仍通过 `utils` 的旧函数名调用日期能力，业务层不需要改接口。
- 跨月、跨年、闰年场景下，逾期衰减可能和 v1.3.1 有不同结果；这是本轮的目标修正。

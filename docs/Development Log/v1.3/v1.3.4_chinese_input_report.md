# v1.3.4 中文自动化输入回归报告

## 【版本号】

- 当前版本：v1.3.4
- 对比版本：v1.3.3

## 【本轮目标】

把中文输入从独立辅助 runner 升级为可重复验证的回归测试，并接入总测试入口。

## 【解决的问题】

- v1.3.3 已支持文本转义和多行，但中文输入仍未进入总回归。
- 旧 `tools/run_utf8_automation.ps1` 只负责把 UTF-8 输入送入程序，没有断言数据文件是否乱码。
- PowerShell 5.1 对无 BOM 脚本中的中文字符串解析不稳定，不能把中文断言直接写在 `.ps1` 源码里。

## 【新增内容】

- 新增 `tests/fixtures/e2e_inputs/chinese_business_flow.txt`，保存中文业务流程输入。
- 新增 `tests/fixtures/e2e_inputs/chinese_expected_fields.txt`，保存中文预期字段。
- 新增 `tests/test_chinese_input_flow.ps1`，读取 UTF-8 fixture 并执行中文业务回归。
- `tools/run_all_tests.ps1` 新增中文输入回归步骤。

## 【修改内容】

- 总测试入口从 CLI、算法、E2E 扩展为 CLI、算法、E2E、中文输入回归。
- README、`docs/testing.md`、`v1.3后续迭代方案.md` 更新为 v1.3.4 状态。

## 【代码级变更】

- `tests/test_chinese_input_flow.ps1`
  - 设置 `Console.InputEncoding`、`Console.OutputEncoding`、`$OutputEncoding` 为 UTF-8。
  - 使用 `[System.IO.File]::ReadAllText(..., UTF8Encoding)` 读取中文输入 fixture。
  - 用独立临时 `--data-dir` 运行程序，避免污染真实 `data/`。
  - 从 expected fixture 读取中文预期字段。
  - 读取 `users.txt`、`cards.txt`、`wrongs.txt`，断言中文用户名、卡片、错题和转卡片内容未乱码。
  - 运行后置 `--check-data`。

- `tests/fixtures/e2e_inputs/chinese_business_flow.txt`
  - 覆盖中文注册、登录、新增卡片、新增错题、错题转卡片和退出流程。

- `tests/fixtures/e2e_inputs/chinese_expected_fields.txt`
  - 保存中文断言字段，避免在 PowerShell 脚本源码中硬编码中文。

- `tools/run_all_tests.ps1`
  - 在普通 E2E 后新增 `Chinese input regression flow` 步骤。

## 【影响范围】

- 影响测试体系，不改变业务功能和数据格式。
- 总测试耗时略有增加，因为新增一次独立中文业务流程。
- 中文 fixture 与真实 `data/` 隔离，不污染用户数据。

## 【验证结果】

已实际执行中文回归：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\test_chinese_input_flow.ps1
```

验证通过，覆盖：

- 中文注册和登录。
- 中文卡片保存与读取。
- 中文错题保存与读取。
- 中文错题转卡片后的内容恢复。
- 后置数据一致性检查。

已实际执行总入口最终验收：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_all_tests.ps1
```

总入口验证通过，覆盖：

- 主程序编译。
- CLI 数据一致性检查。
- 日期与算法单元测试。
- ASCII E2E 业务流程。
- 中文输入回归流程。

## 【已知问题 / 剩余问题】

- v1.3.5 尚未开始：E2E 仍只覆盖核心业务主链路，尚未拆分到主要菜单分支。
- 中文输入回归作为独立 E2E case 接入总入口，还没有并入未来的 `tests/e2e/` 分层目录。
- PowerShell 脚本仍依赖正确设置 UTF-8 编码；本轮已在脚本内显式设置。

## 【下一轮建议】

优先进入 v1.3.5：拆分 E2E case，扩展到用户、卡片、错题、复习、自测、统计、数据维护和 CLI 主要分支。

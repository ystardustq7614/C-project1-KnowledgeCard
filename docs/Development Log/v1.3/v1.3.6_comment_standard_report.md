# v1.3.6 代码注释规范落地报告

## 版本号

- 当前版本：v1.3.6
- 对比版本：v1.3.5

## 本轮目标

按照仓库根目录 `注释要求.md` 的要求，为 `project1` 代码补齐高价值注释：优先说明模块职责、公共接口契约、关键约束、边界条件、副作用和容易误改的位置，而不是逐行翻译代码。

## 解决的问题

- v1.3.5 的注释分布不均：部分头文件只有函数名分组，缺少调用前提、返回语义和副作用说明。
- 部分实现文件存在偏教学解释或逐行复述式注释，维护者仍难以判断哪些参数、字段顺序、排序规则、存储格式不能随意改。
- `card.h`、`wrong.h` 中打印函数声明与实现签名不一致，头文件作为公共契约时会误导调用方。
- `review.h` 仍保留 `calcNextInterval`、`calcNextMastery` 两个无实现的历史声明，增加维护噪声。
- 一键测试在中文输入 E2E 处暴露出 PowerShell helper 命名不一致：脚本调用 `Decode-StorageField`，但部分 helper 只定义 `ConvertFrom-StorageField`。

## 新增内容

- 新增本报告：`docs/Development Log/v1.3/v1.3.6_comment_standard_report.md`，记录本轮注释规范落地范围、验证结果和后续建议。
- 为主要头文件新增模块级注释，统一说明“模块职责 / 不负责 / 关键约束”。

- 为测试 helper 新增 `Decode-StorageField` 兼容别名，保持中文输入 E2E 与分支 E2E 的调用名称一致。

## 影响范围

- 业务行为：除头文件声明清理和测试 helper 兼容别名外，不改变用户交互、数据结构、存储格式和算法结果。
- 编译契约：头文件声明与实现更一致，减少外部调用方误用风险。
- 测试入口：一键测试输出版本更新为 v1.3.6，并修复中文输入 E2E helper 缺失问题。
- 文档版本：README、测试文档和开发日志同步到 v1.3.6。


结果：通过。CLI 数据一致性检查、日期与算法单元测试、核心业务 E2E、中文输入 E2E、用户/卡片/错题/复习练习统计维护分支 E2E 均通过，最终输出 `[v1.3.6] All tests passed`。

## 已知问题 / 剩余问题

- 本轮只对 `src` 和已触发问题的测试 helper 做注释与契约治理，未系统重写所有 PowerShell 测试脚本注释。
- 项目仍采用明文密码、本地文本文件、单进程写入模式，这些限制未在本轮改变。
- 当前注释已经覆盖关键模块，但后续新增功能仍需要在提交时同步维护注释，否则会再次出现注释过期。

## 下一轮建议

- 优先进入 v1.4.0：汇总 v1.3.1 到 v1.3.6，形成稳定闭环版本。
- 次优先：若继续扩展测试脚本，可把测试 helper 全面收敛到 `tests/e2e/common.ps1`，减少重复函数定义。
- 后续新增业务功能时，把“公共接口是否说明契约、复杂逻辑是否说明原因、TODO/FIXME 是否有归属”加入评审清单。

# v1.3.3 文本字段转义与多行输入报告

## 【版本号】

- 当前版本：v1.3.3
- 对比版本：v1.3.2

## 【本轮目标】

让卡片和错题的核心业务文本字段支持 `|` 和多行内容，同时保持文本文件一行一条记录，并兼容旧数据。

## 【解决的问题】

- v1.3.2 以前保存字段时会把 `|`、`\r`、`\n` 替换为空格，用户真实输入会丢失信息。
- 文件格式使用 `|` 分隔字段，直接写入 `|` 会破坏解析。
- 控制台输入只能读单行，卡片正面 / 背面和错题内容无法记录分步骤、多段答案或错因分析。
- E2E 只验证普通 ASCII 单行文本，没有覆盖特殊字符和多行持久化。

## 【新增内容】

- 新增 `encodeStorageField()` / `decodeStorageField()`。
- 新增 `readTextInput()`：普通输入仍为单行；输入 `.multi` 后进入多行模式，单独输入 `.end` 结束。
- E2E 主链路新增包含 `|` 和换行的卡片、错题、错因分析断言。
- 新增本报告：`docs/v1.3.3_text_storage_report.md`。

## 【修改内容】

- `storage.cpp` 保存字符串字段时使用百分号转义，读取时自动解码。
- `card.cpp` 的卡片正面 / 背面改用新文本输入 helper。
- `wrong.cpp` 的题目、正确答案、错误答案、错因分析改用新文本输入 helper。
- `tests/test_e2e_flow.ps1` 新增存储字段解码函数，并断言数据文件中的特殊字符和换行可恢复。
- README、`docs/testing.md`、`v1.3后续迭代方案.md` 更新为 v1.3.3 状态。

## 【代码级变更】

- `src/storage.h`
  - 新增 `encodeStorageField()`。
  - 新增 `decodeStorageField()`。

- `src/storage.cpp`
  - 删除旧 `sanitizeField()` 替换空格逻辑。
  - 新增 `%`、`|`、`\r`、`\n` 的编码和解码。
  - `loadUsers()`、`loadCards()`、`loadWrongs()`、`loadLogs()` 对字符串字段解码。
  - `saveUsers()`、`saveCards()`、`saveWrongs()`、`saveLogs()` 对字符串字段编码。
  - 未编码旧数据仍按原样读取。

- `src/utils.h / src/utils.cpp`
  - 新增 `readTextInput()`。
  - 普通输入直接返回单行内容。
  - `.multi` 模式收集多行，直到 `.end`。

- `src/card.cpp`
  - 新增 `readRequiredTextField()` / `readOptionalTextField()`。
  - 新增卡片和修改卡片的正面 / 背面字段接入多行与 `|` 输入。
  - 学科、章节、标题、标签仍沿用单行输入策略。

- `src/wrong.cpp`
  - 新增 `readRequiredTextField()` / `readOptionalTextField()`。
  - 新增错题和修改错题的题目、正确答案、错误答案、错因分析接入多行与 `|` 输入。
  - 学科、章节、错因类型仍保持原输入策略。

- `tests/test_e2e_flow.ps1`
  - 新增 `Decode-StorageField()`。
  - 卡片正面使用 `.multi` 输入两行，并包含 `|`。
  - 卡片背面包含 `|`。
  - 错题题目、错误答案包含 `|`。
  - 错因分析使用 `.multi` 输入两行，并包含 `|`。
  - 断言原始数据文件中存在 `%0A` / `%7C`，并解码恢复为原始文本。
  - 断言错题转卡片后，生成卡片能保留题目和错因分析内容。

## 【影响范围】

- 影响数据文件中字符串字段的保存格式。
- 新写入的数据会包含 `%25/%7C/%0D/%0A` 转义序列。
- 旧未转义数据仍能读取。
- 卡片和错题详情展示可能显示多行文本，这是预期行为。
- 多行输入会改变 E2E 输入序列，已同步回归脚本。

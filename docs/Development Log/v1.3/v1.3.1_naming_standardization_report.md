# v1.3.1 命名标准化报告

## 【版本号】

- 当前版本：v1.3.1
- 对比版本：v1.3.0

## 【本轮目标】

完成项目命名标准化，让当前目录、默认可执行文件、脚本参数、CLI 帮助文案和文档命令统一使用 `project1` / `project1.exe`。

## 【解决的问题】

- v1.3.0 虽然已经形成测试闭环，但脚本默认仍编译和运行历史带版本 exe 名称，和当前目录 `project1` 不一致。
- `src/main.cpp --help` 输出的用法仍指向旧 exe 名称，用户按帮助执行会得到过时命令。
- README、测试文档和闭环报告中的当前运行命令混用旧目录或旧 exe 名称，增加了后续日期、存储和 E2E 迭代的路径成本。
- 总测试输出中多个测试入口仍使用旧阶段前缀，不利于判断当前验证对应的迭代版本。

## 【新增内容】

- 新增本报告：`docs/v1.3.1_naming_standardization_report.md`。
- 在 README 的版本演进摘要中新增 v1.3.1 记录，说明命名标准化的范围和验证入口。
- 在 `v1.3后续迭代方案.md` 中标记 v1.3.1 已完成，并把下一轮建议更新为 v1.3.2。

- 将主程序默认编译产物统一为 `project1.exe`。
- 将运行脚本和 E2E 脚本默认 `ExePath` 统一为 `.\project1.exe`。
- 将 CLI 帮助文案中的示例命令统一为 `project1.exe`。
- 将 README、`docs/testing.md` 和 v1.3.0 闭环报告中的当前推荐命令统一为 `project1.exe`。
- 将测试脚本阶段输出前缀同步为 `[v1.3.1]`，让总测试日志与当前迭代一致。

## 【影响范围】

- 影响编译输出文件名、测试脚本默认参数、CLI 帮助文本和文档命令。
- 不影响数据文件格式、菜单交互、业务逻辑、算法规则或持久化行为。
- 后续版本可以稳定使用 `project1.exe` 作为默认测试和运行入口。

## 【验证结果】

本轮验证命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_all_tests.ps1
```

已实际执行，结果通过。覆盖结果：

- 主程序编译为 `project1.exe`。
- CLI 数据一致性检查通过。
- 算法单元测试通过。
- E2E 业务流程通过。
- `--help` 输出使用 `project1.exe`。
- 旧命名关键字扫描不再命中文本文件内容。

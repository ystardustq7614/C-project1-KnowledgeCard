# v1.3.8 命名空间治理报告

## 版本号

- 当前版本：v1.3.8
- 对比版本：v1.3.7

## 本轮目标

删除源码和 C++ 测试中的 `using namespace std;`，让代码更接近生产项目的命名空间使用习惯：头文件不向全局命名空间引入任何 `std` 名称，`.cpp` 文件使用窄范围 `using std::xxx;` 或显式 `std::xxx`。

## 解决的问题

- v1.3.7 中多个头文件使用 `using namespace std;`，会污染所有包含该头文件的翻译单元，增加符号冲突和依赖隐式传播风险。
- `wrong.h` 使用 `using std::string;`，虽然范围比 `using namespace std;` 小，但仍会把标准库名称带到包含者的全局命名空间。
- `.cpp` 文件依赖头文件间接带来的 `string/vector/cout/cin` 等名称，可读性和依赖边界不够明确。
- C++ 单元测试也使用 `using namespace std;`，与本轮源码规范不一致。

## 代码级变更

- 头文件治理
  - `src/models.h`：删除 `using namespace std;`，所有模型字段改为 `std::string`。
  - `src/globals.h`：删除 `using namespace std;`，全局容器声明改为 `std::vector`，当前用户名改为 `std::string`。
  - `src/user.h`：删除 `using namespace std;`，用户查找接口参数改为 `std::string`。
  - `src/utils.h`：删除 `using namespace std;`，字符串和日期工具接口全部显式使用 `std::string`。
  - `src/review.h`：复习任务列表和日志接口改为 `std::vector` / `std::string`。
  - `src/wrong.h`：删除 `using std::string;`，错因分类和筛选接口改为 `std::string`。
- 实现文件治理
  - `src/*.cpp`：用 `using std::cout;`、`using std::string;`、`using std::vector;`、`using std::getline;` 等窄范围声明替换 `using namespace std;`。
  - `src/practice.cpp`：将 `chrono::system_clock` 改为显式 `std::chrono::system_clock`。
- C++ 测试治理
  - `tests/test_algorithms.cpp`、`tests/test_date_utils.cpp`：删除 `using namespace std;`，改为按需引入 `std::cout`、`std::cerr`、`std::string`、`std::vector`、`std::to_string`。

## 影响范围

- 业务行为：无变化。
- 存储格式：无变化。
- 测试行为：无变化，测试输出版本前缀更新为 v1.3.8。

```powershell
rg "using std::" src --glob "*.h"
```

结果：无匹配项，确认源码和测试中没有 `using namespace std;`，头文件中没有 `using std::...`。

## 已知问题 / 剩余问题

- `.cpp` 文件仍使用若干窄范围 `using std::xxx;`，这是本轮方案允许的折中，避免一次性把所有标准库名称改成 `std::xxx` 导致大面积噪声。
- PowerShell 测试脚本不是 C++ 命名空间治理对象，本轮仅同步版本前缀。
- 项目仍保留明文密码、本地文本文件、单进程写入等既有限制。

## 下一轮建议

- 优先进入 v1.4.0：汇总 v1.3.1 到 v1.3.8，形成稳定闭环版本。
- 后续新增头文件时继续禁止 `using namespace` 和 `using std::...`。
- 如果继续提高严谨性，可逐步在 `.cpp` 中减少窄范围 `using std::xxx;`，改成关键调用点直接写 `std::xxx`。

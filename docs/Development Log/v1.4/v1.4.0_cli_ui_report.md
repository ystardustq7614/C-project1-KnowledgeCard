# v1.4.0 CLI 界面增强迭代报告

## 版本号

- 当前版本：v1.4.0
- 对比版本：v1.3.8

## 本轮目标

- 在不改变业务流程和数字菜单输入方式的前提下，增强欢迎页和登录后主菜单的终端表现力。
- 借鉴 Claude Code 风格的终端窗口感、状态分区和像素视觉，但避免引入复杂 TUI 框架或运行时脚本依赖。

## 解决的问题

- v1.3.8 的主菜单主要依赖普通文本、颜色和高亮，视觉层次较弱，演示效果不足。
- 欢迎页缺少项目自身的视觉记忆点，不能直观表达“卡片 -> 复习 -> 学习 -> 闭环”的核心链路。
- 主菜单中的推荐、待复习和数据概况分散展示，用户进入系统后不能第一眼看到当前学习状态。

## 新增内容

- 新增 `src/tui.h` 和 `src/tui.cpp`，用于承载轻量终端界面渲染。
- 新增 Claude Code inspired 欢迎页，使用窗口式边框、三色窗口按钮、彩色标题和 `C / R / S / L` 四个小人视觉元素。
- 新增登录后主菜单工作台视图，集中展示当前日期、数据目录、今日待复习数量、有效卡片数、有效错题数和薄弱点推荐。
- 新增统一提示函数，用于错误、提示、警告和成功信息的视觉输出。

## 修改内容

- 修改 `src/main.cpp`，把欢迎页和主菜单的直接 `cout` 输出替换为 `tui` 渲染函数。
- 主菜单不再直接调用旧的推荐展示输出，而是先组装 `TuiMainMenuView`，再交给 `renderMainMenu()` 渲染。
- 保留原有菜单编号和 `getline` 输入方式，自动化脚本仍然可以按原路径输入数字。

## 代码级变更

- `src/tui.h`
  - 新增 `TuiRecommendation`，承载推荐项展示数据。
  - 新增 `TuiMainMenuView`，承载主菜单工作台需要的视图数据。
  - 新增 `TuiNoticeLevel`，统一提示信息类型。
  - 暴露 `renderWelcomeMenu()`、`renderMainMenu()`、`printTuiNotice()` 和 `printTuiPrompt()`。

- `src/tui.cpp`
  - 新增 ANSI True Color 辅助函数和终端框线渲染函数。
  - 新增 UTF-8 显示宽度估算逻辑，用于在中文、ANSI 转义和边框混排时尽量保持对齐。
  - 新增紧凑版 `C / R / S / L` 小人资源，分别对应 `CARD / REVIEW / STUDY / LOOP`。
  - 新增欢迎页和主菜单工作台渲染逻辑。

- `src/main.cpp`
  - 新增 `#include "tui.h"`。
  - 新增 `buildTuiRecommendations()`，把 `algo_recommend` 的结果转换为展示层结构。
  - 新增 `buildMainMenuView()`，统计当前用户有效卡片、有效错题、今日待复习数量、数据目录和推荐项。
  - `showWelcomeMenu()` 改为调用 `renderWelcomeMenu()`。
  - `showMainMenu()` 改为调用 `renderMainMenu(buildMainMenuView())`。
  - 非法输入和退出提示改用 `printTuiNotice()`。

## 影响范围

- 影响欢迎菜单、登录后主菜单、部分入口提示信息的显示方式。
- 不影响用户、卡片、错题、复习、统计、维护等业务模块的数据结构和操作流程。
- 不影响存储格式、命令行参数、`--check-data` 非交互检查或测试数据隔离方式。
- 新增源码文件会被现有 `g++ -std=c++17 -o project1.exe src/*.cpp` 编译命令自动纳入。

## 已知问题 / 剩余问题

- 当前只改造欢迎页和登录后主菜单，卡片、错题、复习、统计等子菜单仍保留原有文本风格。
- 欢迎页使用 Unicode 边框和 ANSI True Color，旧版 Windows CMD 或不支持 ANSI 的终端可能显示降级。
- `terminal_sprites_demo` 当前作为设计素材保留，主程序没有运行时读取 Python 或 JSON。

## 下一轮建议

- P0：继续把子菜单标题、错误提示、成功提示逐步接入 `tui` 模块。
- P1：如果希望更接近 `terminal_sprites.py` 的像素画，可以增加一个生成脚本，把紧凑 ANSI 资源预生成到 C++ 静态字符串。
- P2：评估是否增加 ASCII fallback，改善旧终端的显示降级体验。

# v1.4.3 隐藏内部卡片 ID 热修报告

【版本号】

- 当前版本：v1.4.3
- 对比版本：v1.4.2

【本轮目标】

- 紧急修复交互界面暴露卡片全局 `cardId` 的问题。
- 保留 `cardId` / `linkedCardId` 作为内部持久化主键和关联键，但禁止把这些全局 ID 当作用户可见编号输出。

【解决的问题】

- 新增知识卡片成功后，旧提示会输出真实全局编号，例如第二个账号创建的第九张全局卡片显示为“编号：9”。
- 错题转知识卡片成功、重复转卡拦截、错题详情中的关联卡片、今日复习列表、复习历史和维护检查也存在潜在内部 ID 暴露点。
- 数据一致性检查原本会输出“卡片 ID / 错题 ID”，本轮改为记录位置和问题原因，避免把内部主键暴露给交互用户。

【新增内容】

- 在 `tests/test_e2e_flow.ps1` 增加 ID 隐藏回归断言：
  - 卡片创建成功输出不得匹配旧式“卡片创建成功，编号：数字”。
  - 错题转卡输出不得匹配旧式“已生成新卡片（编号：数字）”。
  - 错题详情输出不得匹配“关联卡片：数字”。
- 新断言使用 Unicode code point 拼接中文模式，避免 PowerShell 5.1 对无 BOM `.ps1` 中文源码解析不稳定。

【修改内容】

- 卡片创建成功提示改为“已加入当前用户的知识卡片列表”，不输出 `cardId`。
- 错题转卡成功提示改为“可在知识卡片管理中查看”，不输出新卡片 `cardId`。
- 错题重复转卡拦截不再显示 `linkedCardId`。
- 错题详情中的“关联卡片”只显示“无 / 已关联”。
- 今日复习列表不再显示底层 `itemId`。
- 复习历史改用本次展示序号，不再输出 `logId` 或 `itemId`。
- 数据一致性检查不再输出卡片 / 错题内部 ID，改用“第 N 条卡片 / 第 N 条错题”描述问题。
- README、测试文档、欢迎页版本号和测试脚本前缀同步到 v1.4.3。

【代码级变更】

- `src/card.cpp`
  - `addCard()` 成功提示移除 `std::to_string(c.cardId)`。
- `src/wrong.cpp`
  - `printWrongDetail()` 隐藏 `linkedCardId` 数值。
  - `addWrong()` 同步隐藏错题内部编号。
  - `convertWrongToCard()` 的重复转换提示和转换成功提示隐藏关联卡片 ID / 新卡片 ID。
- `src/review.cpp`
  - `showTodayTasks()` 删除列表中的底层 `itemId`。
  - `startReviewSession()` 的不可用任务提示不再包含底层 ID。
  - `showReviewHistory()` 使用展示序号替代 `logId` / `itemId`。
- `src/maintenance.cpp`
  - 重复 ID、失效关联、字段范围问题均隐藏内部 ID 值。
  - 报告仍保留问题数量、可修复数量和问题原因，不影响自动修复逻辑。
- `tests/test_e2e_flow.ps1`
  - 增加用户可见输出不泄露卡片 ID 的回归断言。
- `README.md`、`docs/testing.md`、`tools/*.ps1`、`tests/*.ps1`、`src/tui.cpp`
  - 版本标识同步为 v1.4.3。

【影响范围】

- 影响交互输出和非交互检查输出的展示文本。
- 不改变 `cards.txt`、`wrongs.txt`、`review_logs.txt` 的数据结构。
- 不改变错题转卡的内部关联逻辑，`linkedCardId` 仍用于防重复转换和数据一致性检查。
- 不改变用户输入方式，用户仍通过当前列表的连续展示序号操作。

【验证结果】

- 已执行：
  - `g++ -std=c++17 -o project1.exe src/*.cpp`
  - `powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\run_all_tests.ps1`
- 结果：通过，最终输出 `[v1.4.3] All tests passed`。
- E2E 新增断言已确认：
  - `card creation output hides internal card id passed`
  - `wrong conversion output hides generated card id passed`
  - `wrong detail output hides linked card id passed`

【已知问题 / 剩余问题】

- 工作区中的 `data/users.txt`、`data/cards.txt`、`data/wrongs.txt` 仍显示本地修改，这是当前真实业务数据变化；本轮测试仍通过 `--data-dir` 隔离，没有读写真实 `data/`。
- 维护检查中的“第 N 条记录”是文件/容器顺序，不是稳定业务编号；它只用于定位当前检查输出，不应作为长期引用。

【下一轮建议】

- 继续审视所有“编号”文案，把用户可操作的编号统一称为“序号”，把内部持久化字段统一称为“内部 ID”并只出现在文档的数据模型章节。
- 后续可以给非交互 CLI 增加 `--debug-ids` 之类显式调试开关，在默认输出隐藏内部 ID 的同时保留开发排障能力。

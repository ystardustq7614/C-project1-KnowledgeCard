【当前目标】
完成 V1.2 迭代的【阶段 B：多条件查询与物理删除（数据层收尾）】，补齐我们在数据过滤与垃圾回收上遗留的两个刚需功能。

【本轮计划】
1. 在数据维护模块（`maintenance.cpp`）新增“物理删除”功能，彻底从内存和文件中抹除垃圾记录。
2. 在知识卡片（`card.cpp`）与错题模块（`wrong.cpp`）中新增“多条件组合查询”功能，允许跨维度交集过滤。

【实现 / 修改】
完成了以下功能的开发与整合：

**1. 彻底物理删除 (`src/maintenance.cpp`, `src/maintenance.h`)**
- 引入了 STL 的 `<algorithm>` 头文件。
- 实现了 `physicalDeleteInvalidRecords` 函数。
  - 在给出醒目警告和用户确认后，采用极其高效的 `erase-remove_if` 惯用法，从全量 `cards` 和 `wrongs` 动态数组中剔除了属于当前用户且 `active == false` 的记录。
  - 剔除后立刻触发全量序列化 `saveCards()` 和 `saveWrongs()`，用缩减后的数据无情地覆写物理 `.txt` 文件，释放文件空间。
- 在“数据维护”子菜单中新增了选项 `5. 彻底清空回收站`。

**2. 多条件组合查询 (`src/card.cpp`, `src/wrong.cpp`)**
- 新增 `queryCardMultiCondition` 和 `queryWrongMultiCondition`。
- 以向导问答的形式交互：“请输入学科(回车跳过)->章节(回车跳过)->关键字(回车跳过)”。
- 如果用户直接回车跳过某个条件，则该条件自动被视为通配符，不再参与限制拦截。
- 将过滤出的交集数据无缝推入我们在 Phase F 设计好的表现层映射表 (`currentCardMap`) 中，复用了一致的序号打印与详情查看逻辑。
- 将功能分别挂载到卡片与错题的管理菜单中（选项 8 和选项 7）。

【验证方式】
后台执行命令：`g++ src/*.cpp -o project1.exe -std=c++17 -Wall`。
**结果：Exit code 0。所有修改完美融于现有体系，编译通过！**

**【本轮目标】**
补齐 V1 版遗留的数据管理短板：解决长尾垃圾数据累积问题与单一查询效率低下的问题。

**【解决的问题】**
1. 解决了逻辑删除时间久了会导致底层文本文件无限膨胀、拉低 `loadAllData()` 性能的问题。
2. 解决了以前只能单独按学科/按章节/按关键字查，无法快速锁定“高数中关于极限”的具体卡片的问题。

**【新增内容】**
- `maintenance` 模块新增：彻底清空回收站（物理删除）。
- `card` 与 `wrong` 模块新增：多条件组合查询。

**【修改内容】**
- 修改了卡片与错题的管理菜单，为新功能留出坑位。

**【代码级变更】**
- `maintenance.cpp` 中使用了 Lambda 表达式配合 `std::remove_if` 进行条件剔除，没有使用低效的 `for` 循环逐个删除，保证了删除时的 O(N) 性能。
- `queryMultiCondition` 逻辑中通过布尔变量 `match` 与逻辑与（`&&`）操作，优雅地实现了条件的渐进式交集缩减。

**【影响范围】**
- 物理删除功能会永远改变 `cards.txt` 和 `wrongs.txt` 的行数，并在内存中缩短全局向量，这属于高危操作，但已被鉴权与二次确认双重保护。

**【验证结果】**
全量代码编译通过。建议本地运行一下，体验如下流：
删除一张卡片 -> 去数据维护菜单执行“5.物理删除” -> 用记事本打开 `data/cards.txt` 看看那行数据是不是已经人间蒸发了；尝试搜索你设定的“特定学科 + 关键字”，验证交集是否精准。

**【已知问题 / 剩余问题】**
- 组合查询尚未提供“或(OR)”操作，目前全是“且(AND)”的交集查询，但对于日常复习来说完全足够。

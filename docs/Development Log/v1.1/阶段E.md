【当前目标】
完成【阶段 E：数据维护模块】的开发，提供逻辑删除数据的查看与恢复能力，构建项目数据的闭环安全网。

【本轮计划】
1. 新建 `maintenance.h` 和 `maintenance.cpp` 模块，将数据维护职责与日常操作解耦。
2. 实现“查看已删除卡片”、“恢复卡片”、“查看已删除错题”、“恢复错题”四个核心功能。
3. 修改 `main.cpp` 的一级主菜单，挂载“数据维护”入口。

【实现 / 修改】
执行了以下关键修改：

**1. 新建独立模块 `src/maintenance.h` 和 `src/maintenance.cpp`**：
- **查看功能**：遍历全局的 `cards` 和 `wrongs` 容器，专门过滤出当前用户的 `active == false` 的记录并打印出简要信息（错题题干过长时自动做了截断处理）。
- **恢复功能**：输入编号后，程序会校验该记录是否属于当前用户以及是否确实处于逻辑删除状态。校验通过后，将 `active` 置为 `true` 并立刻调用底层持久化接口 `saveCards()` 或 `saveWrongs()` 进行落盘。
- **子菜单组装**：提供了标准且独立的 `showMaintenanceMenu()`，确保数据恢复流程的独立性，不污染卡片/错题日常操作页面的简洁度。

**2. 升级一级入口 `src/main.cpp`**：
- 在主菜单（`showMainMenu`）中，将原“5. 修改密码”下移，正式插入了“5. 数据维护”选项，将子模块接通入主业务流。

【验证方式】
在后台执行：`g++ src/*.cpp -o project1.exe -std=c++17 -Wall`。
**结果：Exit code 0，新增文件与原有系统成功链接，完美编译！**
